# PECMD

以随本 skill 保存的 PECMD 中文手册为语法依据。PECMD 与 Windows CMD 批处理并不等价；遇到不确定的命令、参数、前缀、变量展开或执行时序时，先查手册，不要按 CMD 经验猜测。

## 查阅文档

- 默认检索并读取 [references/cn-utf8.txt](references/cn-utf8.txt)。这是官方中文文档的 UTF-8 转码副本，便于工具无乱码地搜索。
- 需要核对原始编码、原始字节或文档内编码声明时，读取 [references/cn.txt](references/cn.txt)。该文件原样下载自 `https://pecmd.net/doc/cn.txt`，编码为 GBK（代码页 936）。
- 文档较长，只读取当前任务相关的段落。优先用命令名、配置节名、错误文本或关键符号做精确搜索，再展开相邻上下文。

## 工作方式

1. 先确认任务是在编写新脚本、修改现有脚本、解释行为、迁移旧逻辑，还是排查运行错误；同时确认目标 PECMD/WinPE 环境和已有文件编码。
2. 在本地中文手册中验证涉及的每条 PECMD 命令及其参数形式。区分 PECMD 内建命令、CMD 命令、外部程序和项目自定义约定。
3. 修改脚本时保持现有风格、标签、变量命名、换行和编码。除非用户明确要求，不要静默转换 GBK、UTF-8 或其他编码。
4. 给出脚本或补丁时，说明关键执行顺序、条件分支、变量来源和副作用。对文档未说明或依赖具体 PECMD 版本的行为，明确标注为待实机验证，不把推断写成事实。
5. 排错时先构造最小复现，检查命令拼写、分隔符、引号、变量展开、路径、工作目录、文件编码和执行阶段，再考虑外部程序或 PE 环境差异。

## 边界与安全

- PECMD 面向 Windows/WinPE。若把 PECMD 支持接入跨平台代码库，将平台特定实现隔离，并保持对外接口在其他平台可编译和返回明确的不支持错误。
- 对格式化、分区、启动项、注册表、文件删除或覆盖等有破坏性的命令，先确认目标范围；目标含糊时停下并询问，不根据盘符或设备顺序猜测。
- 不把手册示例直接视为适合当前项目的实现。先适配用户提供的目录结构、启动阶段、变量和兼容性要求。
